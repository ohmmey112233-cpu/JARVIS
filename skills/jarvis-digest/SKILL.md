# Digest ของโอม

digest ทุกฉบับ**ถูกส่งโดย cron อยู่แล้ว** (job ชื่อ `jarvis-p1-*` แบบ `--no-agent`)
ตัวข้อความเรนเดอร์โดย `core/digest.py` ให้ตรงกับแบบใน phase1-kit ทุกตัวอักษร
**agent ไม่มีหน้าที่แต่ง digest เอง** — หน้าที่มีแค่ 3 อย่างข้างล่างนี้

## เมื่อไหร่ถึงใช้

- โอมขอดูตอนนี้: "ขอ digest ตอนนี้" / "สรุปเช้าวันนี้ว่าไง" / "ขอสรุปสัปดาห์หน่อย"
- โอมถามเรื่องตาราง: "digest มากี่โมง" / "ตั้ง cron อะไรไว้บ้าง"
- โอมบอกว่า digest ไม่มา / มาผิดเวลา / มาซ้ำ

## หน้าที่ 1 — โอมขอดูตอนนี้: รัน cli แล้วส่งต่อ "คำต่อคำ"

```bash
cd ~/jarvis && PYTHONPATH=jarvis python3 -m cli digest morning
cd ~/jarvis && PYTHONPATH=jarvis python3 -m cli digest evening
cd ~/jarvis && PYTHONPATH=jarvis python3 -m cli digest weekly
cd ~/jarvis && PYTHONPATH=jarvis python3 -m cli digest dream
```

กติกาบังคับ:

1. **ส่งต่อ stdout ทั้งก้อนคำต่อคำ ห้ามเรียบเรียงใหม่ ห้ามย่อ ห้ามเติมหัวท้าย**
   เหตุผล: ข้อความถูกออกแบบตามหลัก 6 ข้อของ kit มาแล้ว (เว้นวรรค อีโมจิ
   ลำดับหัวข้อ ล้วนตั้งใจ) การให้ LLM เล่าซ้ำทำให้ถ้อยคำดริฟต์ทีละนิดจนหลุดแบบ
   และทำให้ digest ที่โอมเห็นจากแชทไม่ตรงกับที่ cron ส่ง — กลายเป็นสองเวอร์ชัน
2. **ห้ามใส่ `--record` ตอนรันตามคำขอ** — `--record` เป็นของ cron เท่านั้น
   ถ้าใส่ไป ระบบจะบันทึกว่า "วันนี้ส่งแล้ว" แล้ว cron รอบจริงของวันนั้นจะเงียบ
   (โอมจะไม่ได้ digest ตอนเช้า) และถ้า cron ส่งไปแล้ว การใส่ `--record` ซ้ำ
   จะทำให้คำสั่งไม่พิมพ์อะไรออกมาเลย ทั้งที่โอมกำลังรอคำตอบอยู่
3. `digest dream` พิมพ์ว่างได้ = **รอบนี้**ไม่มีความจำก้อนใหม่ถูกจัดระเบียบ
   (คำสั่งนี้รันการจัดระเบียบจริง ไม่ใช่ดูย้อนหลัง — cron 06:18 ของเช้านี้
   มักจัดไปก่อนแล้ว ก้อนที่ถูกพักเช้านี้จึงไม่โผล่ซ้ำตอนรันมือ)
   ให้ตอบตามจริงว่า "ตอนนี้ไม่มีความจำที่ถึงเกณฑ์ต้องจัดเพิ่มครับ —
   ถ้าเช้านี้มีการจัดระเบียบ รายงานส่งเข้า Telegram ไปแล้วตอน 06:18"
   **ห้าม**สรุปเองว่า "เมื่อคืนไม่มีอะไรถูกจัดระเบียบ" (อาจมีและรายงานไปแล้ว)
   และห้ามแต่งรายงานขึ้นมาแทน

### ถ้า cli error — ห้ามแต่ง digest ขึ้นมาเอง

คำสั่งล้มเหลว (exit ไม่เป็น 0 / มี `{"ok": false, ...}` ทาง stderr)
→ **บอกโอมตรงๆ ว่าพังตรงไหน พร้อมข้อความ error** เช่น preference ที่ยังไม่ได้กรอก
ห้ามประกอบข้อความหน้าตาเหมือน digest ขึ้นมาแทนเด็ดขาด — digest ปลอมที่ดูสมจริง
อันตรายกว่า error ตรงๆ เพราะโอมจะตัดสินใจ (เวลาออกจากหอ พกร่ม จองร้าน)
จากข้อมูลที่ไม่มีจริง

## หน้าที่ 2 — โอมถามเรื่องตาราง: ดูจาก cron จริง ไม่ตอบจากความจำ

```bash
hermes cron list
```

รายงานเฉพาะ job ที่ชื่อขึ้นต้น `jarvis-p1-` ตารางที่ setup ตั้งไว้ (เวลาไทย):

| job | เวลา | ส่งอะไร |
|---|---|---|
| `jarvis-p1-morning` | 06:20 ทุกวันยกเว้นพุธ | digest เช้า |
| `jarvis-p1-morning-wed` | พุธ 06:00 | digest เช้า (พุธตื่นเร็วกว่าปกติ) |
| `jarvis-p1-dream` | 06:18 ทุกวัน | รายงานความฝัน (เงียบถ้าไม่มีอะไร) |
| `jarvis-p1-evening` | 18:30 ทุกวัน | สรุปเย็น |
| `jarvis-p1-weekly` | อาทิตย์ 20:00 | สรุปสัปดาห์ |

ถ้า `cron list` ไม่มี job พวกนี้ → บอกโอมว่ายังไม่ได้ตั้ง ให้รัน
`bash scripts/phase1-digests-setup.sh` (ห้ามไปสร้าง job เองด้วยชื่ออื่น)

## หน้าที่ 3 — digest ไม่มา/มาซ้ำ: ไล่ตามลำดับนี้

```bash
hermes cron runs        # ยิงจริงไหม ผลรันล่าสุดว่าอะไร
hermes cron status      # scheduler ทำงานอยู่ไหม
hermes gateway status   # gateway ไม่รัน = ไม่มีอะไรถูกส่งเลย
```

- **ไม่มา**: gateway ไม่รัน → บอกให้เปิด `hermes gateway start` /
  cron runs มี error → เอาข้อความ error ไปบอกโอมตรงๆ
- **มาแล้วแต่เงียบรอบสอง**: ปกติ — `--record` กันส่งซ้ำวันเดิมโดยตั้งใจ
  (cron ยิงซ้ำ/เครื่อง restart แล้ว stdout จะว่าง Hermes จึงไม่ส่งอะไร)
- **เนื้อหาผิด**: ห้ามแก้ข้อความเอง — เนื้อหามาจากฐานข้อมูล
  (routines / class_schedule / preferences) ให้ไปแก้ที่ต้นทางผ่าน skill ที่เกี่ยวข้อง
