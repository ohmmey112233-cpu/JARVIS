# Phase 1 — เกณฑ์ตรวจรับ

> คัดจาก `jarvis-phase1-kit.md` ส่วนที่ 4 + เพิ่มวิธีตรวจแต่ละข้อ
> **เกณฑ์: ต้องผ่านทุกข้อ** ห้ามข้ามข้อไหนแล้วบอกว่า "เดี๋ยวค่อยแก้"

เริ่มตรวจได้เมื่อ: gate trial Phase 0B ผ่านครบ 3 ข้อแล้ว และ custom skill ติดตั้งบน VPS แล้ว

## A. ระบบพื้นฐาน

| # | เกณฑ์ | วิธีตรวจ | ผล |
|---|---|---|---|
| A1 | **digest เช้ามาตรงเวลา 7 วันติดกันไม่ขาด** | จดเวลาที่ข้อความถึงทุกเช้า 7 วัน | ☐ |
| A2 | วันพุธ digest มา 06:00 ไม่ใช่ 06:20 | ดูเช้าวันพุธ | ☐ |
| A3 | digest เย็นมาตรงเวลา 7 วันติด | จดเวลา 18:30 ทุกวัน | ☐ |

> A1 คือข้อที่สำคัญที่สุดทั้งหมด — kit เขียนว่า *"cron ที่ทำงานบ้างไม่ทำงานบ้างคือระบบที่ใช้ไม่ได้"*
> ขาดวันไหนให้หาสาเหตุก่อนเริ่มนับใหม่: `hermes cron runs` ดูว่ายิงจริงไหม /
> `journalctl --user -u hermes-gateway --since "06:00"` ดูว่า gateway ตายหรือเปล่า

## E. ความทนทาน (ข้อที่คนมักลืมทดสอบ)

| # | เกณฑ์ | วิธีตรวจ | ผล |
|---|---|---|---|
| E1 | **ปิด VPS แล้วเปิดใหม่ → cron กลับมาทำงานเองโดยไม่ต้องสั่ง** | `sudo reboot` แล้วรอดู digest เช้าถัดไป | ☐ |
| E2 | API ตัวใดตัวหนึ่งล่ม → digest ยังส่งได้ แค่ข้ามหัวข้อนั้น | ตัด API key ของ Air4Thai ชั่วคราวแล้วยิง digest | ☐ |
| E3 | นับโควตา LINE ถูกต้อง เทียบกับตัวเลขจริงใน LINE OA Manager | เทียบเลขสิ้นเดือน | ☐ |
| E4 | **backup ทำงานจริง และ restore ขึ้นมาใช้ได้จริง** | ลอง restore จริง 1 ครั้ง | ☐ |

> E1 ถ้าไม่ผ่านมักเป็นเรื่อง lingering ไม่ใช่เรื่อง cron:
> `loginctl show-user jarvis -p Linger` ต้องได้ `Linger=yes`
>
> E4 — kit เขียนว่า *"backup ที่ไม่เคยทดสอบ restore ถือว่ายังไม่มี backup"*
> ต้อง restore ขึ้นมาแล้วเปิดใช้งานได้จริง ไม่ใช่แค่ไฟล์ดาวน์โหลดมาได้

## F. เกณฑ์สุดท้าย — ข้อที่ตัดสินว่าจะไปต่อไหม

> **ใช้จริง 1 เดือนเต็ม แล้วตอบคำถามเดียว:**
>
> ### "เดือนที่ผ่านมา เปิดอ่าน digest เช้ากี่วันจาก 30 วัน?"

```
จำนวนวันที่เปิดอ่านจริง: ______ / 30
```

| ผล | แปลว่า | ทำอะไรต่อ |
|---|---|---|
| **≥ 25 วัน** | ระบบนี้มีค่ากับชีวิตจริง | ไปต่อ Phase 2 ได้ |
| **10-24 วัน** | เนื้อหายังไม่ตรงใจ | แก้เนื้อหาข้อความก่อน **อย่าเพิ่งสร้างฟีเจอร์ใหม่** |
| **< 10 วัน** | ไม่ได้ใช้จริง | **หยุด** — ประหยัดเงินหลักหมื่นจากการไม่ซื้อ smart home และประหยัดเวลาช่วง TCAS |

> ข้อนี้ตอบตัวเองตรงๆ ไม่ต้องเกรงใจระบบที่สร้างมา — red-team H15 เตือนว่า
> *"ทรัพยากรที่ขาดจริงในโปรเจกต์นี้คือเวลาและความสนใจ ไม่ใช่เงิน"*
> ปีนี้เป็น ม.6 เตรียม TCAS ซึ่ง *"กลับไปแก้ทีหลังไม่ได้ ต่างจากโปรเจกต์นี้ที่เลื่อนได้"*

## รันเทสต์ของโค้ดแกน (ทำได้ทุกเมื่อ ไม่ต้องมี VPS)

```bash
cd ~/jarvis && PYTHONPATH=jarvis python3 -m unittest discover -s jarvis/tests -v
```

เทสต์พวกนี้ครอบคลุมตรรกะที่พังเงียบได้ง่ายที่สุด — วันที่แบบไทย ศุกร์สลับสัปดาห์
รอบ routine ความจำที่ทับกัน และการที่ digest ต้องไม่พังตอน API ล่ม
**ผ่านหมด ≠ Phase 1 ผ่าน** แต่ไม่ผ่านคือยังไม่ต้องไปตรวจข้อ A-F ให้เสียเวลา
